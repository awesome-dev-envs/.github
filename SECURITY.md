# Security Policy

## Scope

This policy covers the **Awesome Developer Environments repositories and organization** — including setup scripts, documentation, templates, workflows, and automated tooling setup.

If you find an issue or vulnerability within a **third-party tool or package** installed by our scripts (once successfully installed), please report it directly to that tool's maintainers or owners, not here.

You can also suggest replacing one tool with another by submitting an improvement issue for us.

## Supported Versions

This is a community-maintained open source project provided as-is.
There are no formal support commitments or versioned releases.  
The maintainers will do their best to address reports promptly and responsibly.

## Reporting Issues and Vulnerabilities

- **Automated Script/Security Flaws/Documentations:** If you discover a vulnerability or flaw in our repository scripts or automation logic, please open a [bug issue](https://github.com/awesome-dev-envs/.github/issues/new).
- **Tool Additions/Changes:** If you wish to suggest including, modifying, or removing a tool, please open an [improvement issue](https://github.com/awesome-dev-envs/.github/issues/new), or request access and submit a Pull Request.

When reporting an issue, please include:

- A clear description of the vulnerability, flaw, or improvement
- Steps to reproduce (if applicable)
- The potential impact
- A suggested fix or implementation (if you have one)

The maintainers will review and respond as quickly as possible.

## Past Incidents

We believe in transparency.
Security issues that have been identified and fixed are tracked in the public issue history of this repository.
